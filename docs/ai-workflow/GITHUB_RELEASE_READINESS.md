# GitHub Release Readiness

This checklist distinguishes local technical evidence, exact-SHA remote gates,
owner decisions, and immutable publication. A local candidate is not a
published release.

The repository is licensed under the Apache License 2.0; release candidates
must retain the tracked `LICENSE` and `NOTICE` files.

## Local candidate gate

- [ ] The active Task Issue contract is verified and its base SHA is frozen.
- [ ] Offline cache, if used, returns `CACHED`, has a valid digest, and does
  not claim remote checks.
- [ ] `py -3 -B -m unittest discover -s tests` passes, plus focused governance,
  Run Guard, Template Doctor, and release-readiness suites.
- [ ] `bash scripts/verify.sh` and `bash evals/run-evals.sh` pass with native
  exit codes checked individually.
- [ ] Template Doctor is ready; optional CodeGraph absence remains explicit.
- [ ] `py -3 -B -m tools.governance_v2 gate static --root .` returns
  `STATIC_TARGETED_PASS`.
- [ ] Release-candidate builds a deterministic candidate, verifies clean
  extraction, emits payload/provenance/release-set summaries, and has no write
  permission or tag/Release command.
- [ ] Release inventory excludes `.aiwf/`, caches, runtime evidence, and
  retired active control files.
- [ ] No secrets, local absolute paths, generated bytecode, or untracked
  runtime outputs are in the candidate source tree.

## Remote gate

Before a remote merge, `gate github` must bind the expected workflow and
Check Run to the exact PR head SHA. The workflow must be active, jobs must be
non-empty and successful, the Check Run conclusion must be `success`, and the
required GitHub App ID/context must match. Missing, skipped, neutral, partial,
or API-inaccessible evidence is not success.

PR A does not add `release-candidate` to required checks and does not perform
Bootstrap A/B. Stop for user review before squash merge. Required checks,
rulesets, immutable releases, tags, and Release provenance belong to later
owner-approved stages.

## Source and release artifact separation

Use `git archive HEAD` for a clean source snapshot. Use
`scripts/build-release.py` plus the independent archive verifier for formal
release artifacts. Never zip the working directory. A release builder must
read release files from committed HEAD and reject dirty, untracked, deleted,
or locally divergent release content.

## Owner decisions and post-merge stages

The owner must separately approve license/attribution, remote repository
settings, branch protection, merge, tag, and publication. After PR A is merged,
re-read exact base/head facts, perform Bootstrap A, then Bootstrap B and Release
Freeze. Do not start PR B automatically. PR B introduces product/release
migration, v2.0.0, formal release notes, immutable provenance, and final
publication checks.
